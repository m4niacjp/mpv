add `--prefetch-playlist-on-cache`, `--prefetch-playlist-cache-secs`,
`--prefetch-playlist-cache-bytes`, `--prefetch-playlist-max`,
`--prefetch-playlist-realtime`, `--prefetch-playlist-start-secs`, and
`--prefetch-playlist-start-bytes` options

`--prefetch-playlist=yes` prefetches future playlist entries when the current
URL is fully read, retaining up to `--prefetch-playlist-max` entries (default:
1). `--prefetch-playlist-on-cache=yes` makes that prefetch start earlier, after
the current entry reaches its effective demuxer/cache readahead target or byte
limit. The cache options cap how much each prefetched entry reads ahead; 0
keeps the normal demuxer/cache settings.

`--prefetch-playlist-max` limits how many future playlist entries are retained
prefetched at once. It defaults to 1, preserving the previous single-next-entry
behavior. Each retained entry can fill its bounded cache concurrently, so
raising the limit can multiply disk or network I/O and memory use.

`--prefetch-playlist-realtime=yes` requires `--prefetch-playlist=yes` and
immediately starts the configured future set without waiting for the current
URL to reach EOF or its cache/readahead target. The cache caps remain per
future entry, and simultaneous reads can compete for disk or network I/O.

`--prefetch-playlist-start-secs` (default: 10) and
`--prefetch-playlist-start-bytes` (default: 32MiB) fill a small start window
for the immediate next entry first. Extra retained entries are not opened until
that window is full and the current demuxer is not underrunning. Set both to 0
to fill the full prefetch cache caps immediately. Prefetch selects audio and
video tracks only; subtitle and attached-image tracks are left to normal
selection on adopt.

Playlist-move, playlist-reorder, shuffle, unshuffle, remove, and clear retarget
`--prefetch-playlist` to the new next entries instead of retaining a stale
previous next.
